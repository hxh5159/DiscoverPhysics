联网CPU实例构建镜像 → 无网4卡H200运行（CUDA12.8）

一、两个阶段
CPU实例负责安装、编译和下载离线资源，不要求有GPU或nvidia-smi。
H200实例只做本地验收和推理，不执行pip/conda/git或联网下载。
当前版本仍为Python3.12、torch2.11+cu128、vLLM0.24源码、transformers5.8。

环境与编译工具建议放在镜像会保存的/opt目录，示例：
  /opt/shore-h200-cu128         双Python环境、Python解释器、缓存及构建清单
  /opt/shore-h200-toolchain     CUDA12.8、GCC/G++12、git、curl、make
  /opt/shore-image-tools-v5    七份匹配的安装/准备/检查组件（旧v4保留）
在平台保存镜像前确认这些路径属于会打包的文件系统。
/inspire/...共享盘的项目与模型在H200实例中另行挂载；不能默认挂载盘会随镜像复制。
镜像部署后保持相同绝对路径，不仅复制venv目录。

二、CPU实例：编译
准备完整CUDA Toolkit12.8与GCC/G++11.3—14，无须安装GPU驱动。
使用bootstrap_cuda128.sh的显式CPU构建模式：
脚本所在目录还须包含pip_index_install.py、preflight_cuda128_build.py、
prepare_vllm_dependencies.py、prepare_torch_wheel.py，须从同一完整版本取得，不混用旧组件。

export SHORE_CUDA128_HOME=/opt/shore-h200-toolchain
export CC=/opt/shore-h200-toolchain/bin/x86_64-conda-linux-gnu-gcc
export CXX=/opt/shore-h200-toolchain/bin/x86_64-conda-linux-gnu-g++
export PATH="$SHORE_CUDA128_HOME/bin:$HOME/.local/bin:$PATH"
export SHORE_BUILD_JOBS=2

bash /opt/shore-image-tools-v5/bootstrap_cuda128.sh \
  --cpu-build-for h200 --env-root /opt/shore-h200-cu128 \
  --index-url 'http://nexus.sii.shaipower.online/repository/pypi/simple' \
  --trusted-host 'nexus.sii.shaipower.online' --mirror-only

该模式强制VLLM_TARGET_DEVICE=cuda、TORCH_CUDA_ARCH_LIST=9.0。
通用内核以SM90编译，专用Hopper内核按vLLM自身规则使用SM90a。
同时固定Triton使用已核验的CUDA12.8 ptxas，避免回退到其他版本的汇编器。
它检查CPU计算、包版本与扩展文件存在，不要求CUDA初始化、卡数、GPU计算或CLI导入。
生成cuda128-build-manifest.json，明确GPU与模型验收未完成。
旧架构已装环境不静默当作H200构建复用；需要新目录时保留旧环境。

三、CPU实例：下载离线内核
安装完成后执行：

python3 /opt/shore-image-tools-v5/prepare_h200_offline_cache.py \
  --env-root /opt/shore-h200-cu128 \
  --index-url 'http://nexus.sii.shaipower.online/repository/pypi/simple' \
  --trusted-host 'nexus.sii.shaipower.online' --mirror-only

python3 /opt/shore-image-tools-v5/prepare_h200_offline_cache.py \
  --env-root /opt/shore-h200-cu128 --verify

工具仅按指定镜像安装flashinfer-jit-cache0.6.12+cu128，缺少精确包时停止，不添加官方wheel源。
同版cubin属于独立非pip资源，仍需访问其官方服务；
核对官方注册表及本地文件，生成offline-kernel-cache.json。
flashinfer-cubin已安装时其包内目录优先于自定义CUBIN_DIR，清单记录实际路径。
不要使用旧0.32说明中的vllm download-kernels；0.24没有这个CLI命令。
prepare阶段需要网络，--verify仅查本地文件，不导入FlashInfer、不执行子进程。
CPU无法为所有模型运行形状预热；H200首次运行仍允许使用随镜像保留的工具链做本地JIT。

以上两阶段成功后再保存镜像。镜像中同时保留整个环境目录、解释器、Toolkit、
GCC/G++、Ninja、headers与已下载的内核，不能只保存pip列表或只保留Python包。
Toolkit的stub库可用于链接，不得加入运行LD_LIBRARY_PATH；真实驱动由H200运行环境提供。

四、H200实例：离线验收
先确认平台已分配四张完整H200并挂载项目/模型共享盘，再执行：

source /opt/shore-h200-cu128/activate_h200_offline.sh
python3 /opt/shore-image-tools-v5/verify_h200_cuda128.py \
  --env-root /opt/shore-h200-cu128

激活文件固定本地缓存，开启HF离线与FlashInfer禁止下载；保留本地JIT能力。
验证器不安装/联网/启动模型，检查构建清单、内核文件SHA、四H200/SM90、
实际BF16计算、CUDA扩展、依赖、编译器与缓存可写性。
基础检查通过仍不代表模型权重、FP8或多卡推理已经通过。

五、H200实例：真实模型验收
模型必须是已挂载的完整本地目录，不能传需联网下载的仓库ID。例如：

vllm serve '/实际本地Qwen3.8-27B目录' \
  --host 127.0.0.1 --port 8000 --served-model-name Qwen3.8-27B \
  --tensor-parallel-size 4 --dtype bfloat16 \
  --max-model-len 32768 --max-num-seqs 1 --gpu-memory-utilization 0.90 \
  --enforce-eager --reasoning-parser qwen3 \
  --limit-mm-per-prompt '{"image":0,"video":0}'

在同节点另一终端用项目已有HTTP客户端验证一次真实生成，再运行实验/评分。
实验端使用/opt/shore-h200-cu128/.venv-trial/bin/python，模型端使用独立vLLM进程。
H200无网络时若缺少文件，应停止并回到联网CPU端补齐，更新镜像后重试。
不把CPU构建/缓存准备成功称为H200实机推理已通过；交付脚本仅做本地离线逻辑检查。
