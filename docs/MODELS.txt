本地模型选择、加载与实际模型路径
版本：1.1.0；环境：现行CUDA12.8 / vLLM0.24.0配置。

一、当前白名单与五个起步配置

模型目录默认：/inspire/hdd/project/26-the-other-shore/public/models
固定映射见rift/model_catalog.json，可用python scripts/serve_model.py --list查看。

选择键        实际模型变体                    存储精度
27b           Qwen3.8-27B                    BF16
35b           Qwen3.6-35B-A3B                BF16
35b-fp8       Qwen3.6-35B-A3B-FP8            FP8
122b          Qwen3.5-122B-A10B              BF16
122b-fp8      Qwen3.5-122B-A10B-FP8          FP8

为避免在模型选择上带来分歧和差距，故保留以上几个模型；同时考虑算力资源和微调所需
算力，不再保留需要4卡才能加载的模型。以上五个配置属于三个Qwen模型家族；白名单仅限
上述模型及其合法量化、SFT或RL衍生权重，不包括其他Qwen型号或其他系列模型。
所需显卡数量仍取决于所用精度、上下文与设备显存，不保证任意硬件均可用相同卡数运行。

35b-fp8优先识别用户提供的Qwen-3.6-35B-A3B-FP8目录，也接受没有额外横杠的别名。
映射不会重命名文件或改变精度。自行量化时仍声明原白名单底座和实际检查点路径，并使用
与其真实精度兼容的部署配置；不能借此使用未列出的底座或外部模型API。

二、先看配置，再启动模型

以下命令在远端Linux的参赛包/项目根目录执行：

python scripts/serve_model.py --model 27b --plan-only

此项只打印配置，不要求模型文件、GPU或vLLM已安装。

python scripts/serve_model.py --model 27b --dry-run

此项检查本地config、tokenizer和safetensors头部，不加载权重或查询GPU。
有自训的完整推理检查点时可加--model-path /实际检查点目录，并按其真实精度选择配置。

python scripts/serve_model.py --model 27b \
  --model-python /opt/shore-h200-cu128/.venv-vllm-cu128/bin/python \
  --tp-size 4 --port 8000

实际启动前会用模型环境检查vLLM0.24、Torch CUDA12.8、可见GPU和基础显存容量。
不安装库、不下载模型、不更改CUDA_VISIBLE_DEVICES，不请求在线量化。
397B及原非Qwen系列均已退出白名单，启动与提交校验不再接受其名称或旧选择键。
能通过容量检查不等于KV缓存、MoE内核和实际生成已经验收。

三、同一基础agent的两种加载方式

使用既有本机服务：
  --model 27b --base-url http://127.0.0.1:8000/v1

自动启动本机服务：
  --model 27b --model-root /实际模型根目录 --model-python /实际模型环境/bin/python

对应命令行由六公开开发驱动或正式提交entrypoint传递。自动加载在首次mission之前完成，
不占每宇宙300秒探索窗口；模型服务就绪后才进入宇宙。基础框架支持更改提示词、工具、
记忆和程序，提交时须保留这些策略代码，不能只提交未包含策略的模型权重。

单个白名单模型可加载多个运行实例，用于多个智能体。同源权重可由这些实例共用，
无须重复复制；models.json可登记一个共享模型ID。不同微调结果仍按不同ID和路径登记。
实例数量及其显存、进程和推理开销由本队策略在统一资源限制内安排。

已有服务地址只接受显式本机HTTP回环，禁止代理和重定向，不提供闭源API回退。
服务自报的model名称用于发现配置，不是权重来源证明；来源核查仍由指挥部执行。
模型回复只有思考、没有最终动作时，不把思考内容当作实验指令执行。

四、策略目录与实际模型路径

正式评测读取提交的agent目录和models.json。清单使用实际/inspire/...模型路径或相对
清单的检查点路径，入口和清单声明应对应同一份模型。SHORE_MODEL_ROOT、--model-root或
--model-path明确指定本次权重；旧/models路径只作为可选兼容，不要求建立路径映射。
测评期间禁止编辑配置和改写所用权重；需要复用本机服务时，先确认服务已重载最新检查点。

实验环境与模型环境可以分开。自动启动优先SHORE_MODEL_PYTHON、再使用已存在的
/opt/shore-h200-cu128/.venv-vllm-cu128/bin/python。工具链和只读预下载内核随CPU镜像保留，
启动器可读取镜像的cuda128-build-manifest.json恢复CUDA_HOME、CC/CXX与PTX路径。
HF、vLLM、Triton、FlashInfer和Torch可写JIT缓存放在本局产物目录的model-service/.cache，
不会尝试往只读/opt目录写缓存；H200端保持离线，缺依赖/模型文件时返回明确错误。

当前启动器与旧指挥部0.32/cu129 serve_open_models.py分开；不要混用其版本检查或
在线量化参数。接口参考：https://docs.vllm.ai/en/v0.24.0/cli/serve/
以及 https://docs.vllm.ai/en/v0.24.0/serving/online_serving/openai_compatible_server/
