模型与单实例运行环境

一、两个Python环境

实验/拟合/控制台：/opt/shore-h200-cu128/.venv-trial/bin/python。
模型服务：/opt/shore-h200-cu128/.venv-vllm-cu128/bin/python。
可通过--model-python或SHORE_MODEL_PYTHON明确改变模型Python；不把base环境当作已配置环境。
当前推理环境为CUDA12.8；新入口scripts/serve_model.py针对同一固定版本，不调用旧启动器。

默认权重根目录：/inspire/hdd/project/26-the-other-shore/public/models。
五个目录和精度映射见rift/model_catalog.json；35b-fp8兼容已有额外连字符的目录名。
正式测评直接读取队伍配置的实际模型或checkpoint路径，不要求复制到参赛ZIP或映射/models。
目录别名、服务显示名和精度是不同概念：程序按本地配置与分片头部核查，不能改名字冒充FP8。
模型已训练或合并时，入口使用已保存完成的实际检查点；LoRA等方式使用已验证的底座与adapter加载流程。
提示词、工具和配置全部放在提交的agent目录，测评期间停止编辑和改写所用权重。
同一个白名单模型可加载多个实例，多个智能体可共用同源权重路径，无须复制多份模型。
使用同源权重时可共用一个模型ID，不同微调结果分别登记；总资源消耗仍受统一限制。

二、基本启动方式

python scripts/serve_model.py --list
  只列五个模型配置，不加载权重、不查询GPU。
python scripts/serve_model.py --model 27b --plan-only
  只输出路径和启动参数，不要求模型目录存在，不调用GPU或服务。
python scripts/serve_model.py --model 27b --model-root <本地根目录> --dry-run
  检查配置及safetensors头部，不读取完整权重、不加载模型。
python scripts/serve_model.py --model 27b --model-root <本地根目录> --model-python <模型Python>
  在实际GPU节点启动本地vLLM服务。未提供--base-url时，基础agent也可自动执行此过程。

固定单宇宙600秒从mission之后开始；服务加载有独立startup-timeout。
客户端只接显式本机服务，不使用环境代理或外部模型回退。服务名称本身不能证明权重来源。
实际执行会检查所选设备的容量。白名单仅保留27B、35B-A3B、122B-A10B三个Qwen家族及
规定的精度配置，397B和原非Qwen模型已移除；具体名称及选择原因见MODELS.txt。
低显存或不兼容时明确失败，不静默转换精度。基础命令默认TP4和32K上下文。

三、离线环境与缓存

模型子进程从CPU镜像的构建清单恢复CUDA/编译器/PTX路径。可写HF、vLLM、Triton、
FlashInfer工作区等放到本次输出目录下.cache；镜像内预下载的cubin/AOT依赖保持只读。
H200不联网下载模型、包或内核。CPU保存镜像前应完成H200_OFFLINE_SETUP.txt的安装与缓存阶段。
仅安装包成功不保证实际模型兼容，先做真实生成，再做整套实验。检查报告会区分这两个层级。

四、提交策略与权重路径

各队保留agent/run.py入口及Console、law.py/claims.json接口，向指挥部提交agent目录和
models.json两类绝对路径。多个子智能体和多份权重使用统一入口与模型ID协调。
九个测评宇宙由指挥部运行；攻坚组无需接收真实模拟器或自行上传模型权重副本。

模型推理环境使用--model-python或SHORE_MODEL_PYTHON。需要其它依赖的策略在提交前
自行完成同环境自测，并确保完整策略和全部权重路径可读取。
若复用模型服务，更新权重后应重新加载，避免继续使用旧进程中的权重。

本机官方控制台服务负责真实实验，队伍程序通过Console自动请求数据；固定候选积分和
最终评分由指挥部组件执行。九宇宙运行材料由指挥部保留，只反馈规定成绩。
