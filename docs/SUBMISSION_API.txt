提交接口：策略目录与模型路径清单

当前正式接口为两类路径：agent目录的绝对路径、models.json的绝对路径。
策略结构、完整字段、多智能体/多checkpoint例子及命令见STRATEGY_SUBMISSION.txt。

agent/strategy.json只声明schema_version=1.0.0、team_id、submission_id、version。
入口固定为agent/run.py，多个子智能体统一由该入口协调。全部自定义策略资产在agent/。
models.json声明schema_version=1.0.0、primary_model_id、models数组。
每项必填唯一id、白名单base_model和path，可声明role、adaptation、adapter_path。
完整权重在path；LoRA在adapter_path并同时给底座path。相对路径以models.json父目录为准。
同一底座的多份训练结果使用不同ID和不同权重/适配器路径。

rift.strategy提供load_model_registry、model_binding、check_strategy_files与load_strategy_submission。
控制台会话和RIFT_OUTPUT_DIR由指挥部提供，模型清单位置通过SHORE_MODEL_REGISTRY提供。
固定SDK位置通过SHORE_SDK_ROOT提供，自定义模块使用agent包内的相对导入。
指挥部检查所有声明的模型和适配器，不因默认只加载primary而漏收其他权重。
运行期间保持代码、配置、检查点稳定，不将未保存完成的checkpoint作为本窗模型。

六公开开发和正式评测使用同一启动器及Console/law.py/claims.json协议。
正式命令在指挥部执行evaluate_strategy.py；不从队伍项目读取真实模拟器或评分代码。
当前正式集合Adam、Ramiel、Leliel，三档权重0.3/0.4/0.3，其他六界定义和参考仍保留。
正式运行每次独立，榜单取最佳完整一次，不拼接逐宇宙历史最高分。
赛中只返回总分和所测各宇宙总分，隐藏日志、观测、新记忆和更新权重不归还队伍。

旧submission.json/entrypoint接口用于历史运行兼容；新提交按本文件的目录和模型清单执行。
内部运行器可将上述两份小清单规范化为旧记录结构，以复用配对交卷和榜单代码。
