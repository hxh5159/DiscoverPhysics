参赛交付与运行就绪检查
检查日期：2026-11-02（北京时间）
检查基线：项目1441e5f；测试资料9b895f4；starter-v3／校准r5／internal-v8。

一、结论

当前不满足“仅安装依赖、准备模型，就能直接用官方基础框架完成六公开开发和九隐藏评测”。
已有公开数值原型、统一候选积分、格式校验和指挥部运行模块，但可运行的模型基础框架、
六公开统一驱动、新正式配置和最终发放包尚未闭合。不能把接口测试通过称为完整参赛就绪。
本轮是检查，没有借此修改力场、评分、预算、模型范围或现场运行方式。

九宇宙仍为隐藏正式评测环境：由指挥部运行攻坚组提交的完整程序和模型成果。
攻坚组无需取得九宇宙源码，也不应在自己的目录部署九宇宙真实环境。

二、文件边界与实际交付

攻坚组可改：
  自己的智能体程序、提示词、记忆、工具、训练/推理配置、提交清单和候选law.py。
  当前examples/agent.py只有接口占位：不加载模型，直接提交零加速度及任意格式猜测。
  原则上应提供的“可修改但能直接运行的LLM基础框架”尚未由此占位实现替代。

攻坚组可见、正式运行采用固定版本：
  rift/、rift_numerics/、格式检查器、接口和计分契约。
  六公开development_worlds/的模拟器、目录和自测计分程序应作为开发资料提供。
  现starter-v3实际31文件只含SDK、积分器、部分契约及示例，尚不包含development_worlds/。

指挥部运行专用：
  九隐藏真实模拟器、定律配置、声明真值、验证参考，以及正式实验服务、调度、评分、
  队列、榜单和冻结执行配置。模型由可信挂载或制品登记接入，不随参赛ZIP附带大权重。
  测试资料库的访问权限由所有者另行决定，不等于整库就是参赛发放包。

不直接随参赛包发放：
  项目AGENTS.md、原研究工程和研究资料、指挥部运行包、内部校准程序及原始运行日志。

三、已实际验证的层级

1. starter-v3：CRC、清单哈希、白名单与当前源码匹配；未混入正式九宇宙的模拟器、
   参数、声明真值或验证数据。清单、claims、law接口和假例固定积分可独立运行。
2. 六公开：仅显式补入公开development_worlds/后，六界均完成CPU级mission、observe、
   launch、archive及候选law.py固定积分评分。这个增强目录不是当前已发的starter-v3。
3. 两侧计分：45组预言映射及200组声明/能量/门槛组合逐值一致；均为80/(1+10e)、
   80/15/5、P>=40后计节约。600秒、0.005严格网格和噪声1.1.0约定一致。
4. 指挥部当前v8包在隔离解压目录、内部诊断模式下，以原始占位agent顺序完成九界：
   领取任务、生成并提交law.py/claims.json、固定积分、评分、受限成绩反馈，约76秒。
   九界均核验有效提交和候选摘要；这不是仅启动CLI或队列显示completed的检查。
   该agent不调用模型，发布配置仍为内部验证；此检查不能代替新科学版本接入、真实
   LLM发现、目标Linux容器权限或GPU运行验收。

四、阻止开箱运行的具体缺口

1. 缺实际LLM基础框架。
   examples/agent.py不调用模型；安装vLLM或下载权重不会自动让它开始探索。
   旧研究ScienceAgent和指挥部JSON表达式校准程序也不是已完成的正式law.py参赛基线。

2. 六公开开发流程尚未接统一接口。
   DevelopmentConsole是本地对象，仅有mission/observe/launch/archive；尚无与正式
   rift.Console共用的服务适配、save_draft/submit配对收卷和六界完整调度。
   单纯把六公开源码加入ZIP，还不足以让同一个agent无改动切到九隐藏。

3. 正式九界配置尚未冻结和接入最新设计。
   internal-v8仍继承旧版科学定义和验证参考，未完成后来设计修订的迁入。
   profile仍为internal_validation，发布/资源/范围批准均false，candidate_image为空、
   model_mounts为空。正式入口会拒绝该配置；不能只把批准标志改true来代替实际配置验收。

4. 模型和环境入口尚未统一。
   当前旧serve_open_models仅有27b/122b/397b预设，并拒绝最新cu128环境的vLLM0.24。
   新环境说明要求直接用新版vllm serve；旧一键脚本不能视为已兼容的新基线入口。
   七个提供目录、模型家族标识、精度、served名称和容器/models挂载尚未统一映射；
   有些目录名照抄为base_model会被旧校验器拒绝，不表示本次检查重新限定了允许模型。

5. 赛中不归还隐藏材料的新政策尚未落到所有入口。
   现正式驱动仍生成team-export，旧导出器仍可由指挥部导出mission/archive/候选及agent输出，
   部分契约仍写可以归还。并非已经自动返给攻坚组，但交付前应关闭这条旧通道并同步说明。
   正式反馈保留加权总分、各宇宙总分及必要启动/格式错误。

五、达到交付标准需要完成的验收

先完成同一LLM基础agent和公开/隐藏统一控制台驱动，再制作含六公开开发集的新版参赛包；
同步最新九界科学版本、模型制品/挂载/镜像配置和隐藏材料留存政策。
之后分别在“仅解压参赛包”的干净目录验证六公开完整运行，并由指挥部在隔离环境验证
同一提交进入九隐藏、自动产生law.py/claims、固定积分计分和受限反馈。
最后在目标无网4H200上实际加载所选模型、完成一次真实生成和完整运行。

本轮没有访问用户远端，没有加载模型或调用模型API；尚不能保证所有提供目录的模型
在同一硬件配置均可加载。以上缺口与依赖安装、模型文件是否已经准备好是不同层级。
