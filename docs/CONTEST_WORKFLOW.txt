正式参赛运行流程与交付边界 1.2.0（直接项目运行）

攻坚组保留当前项目和submission.json约定的程序入口及模型路径。窗口开始后停止编辑；
指挥部接入九宇宙环境，在本队项目目录直接运行同一入口，依次完成九个宇宙。每个宇宙内由智能体自主请求实验、拟合和检验候选规律，最终产生law.py与claims.json；指挥部固定积分、评分，再汇总整次提交的成绩。

一、从哪里开始

开发包包含六公开宇宙、可修改的LLM基础框架、控制台客户端、固定候选积分器、提交模板、格式检查器和接口文档。先按QUICKSTART.txt加载所选模型并运行development_worlds.runner；同一基础agent由指挥部正式驱动进入九隐藏宇宙。公开开发成绩不进入榜单。
CONSOLE_API.txt说明如何请求观测，LAW_API.txt说明候选加速度与固定推演，SUBMISSION_API.txt说明直接项目启动与清单。
正式宇宙的真实模拟器源码、私有配置和验证真值不随包分发。

二、单个宇宙的流程

1. 运行器提供本局控制台地址、授权令牌和可写产物目录。基础agent先加载本地模型或核验已启动的本机服务；模型加载不占探索600秒。
2. 智能体调用mission，取得任务、合法操作范围、公开初态与第一束光，并开始本局墙钟。
3. 智能体通过observe/launch自动实验，使用允许数据分析和拟合。对候选规律的轨迹检验调用固定rift.rollout，不查询真实宇宙、不扣实验能量。
4. 调用save_draft保存有效law.py/claims.json配对；修正格式错误后可重试。调用submit成功后结束该局。
5. 超时封存最后一份及时有效配对；没有有效配对则该宇宙0分。队伍进程提前退出会结束该局并保留最后有效配对；指挥部基础设施故障单独处理，不伪装成科学零分。
6. 指挥部将允许的验证初态与时刻交给固定驱动，调用law.py生成预测轨迹，再与无噪真值比较。

各局会话和配额独立；重复mission不能重置本局。物理时间、实验能量、现实墙钟的含义按公开协议执行，不由客户端自行记账。直接正式入口使用指挥部direct-v1-r2运行配置；启动护栏900秒、候选执行120秒、关闭护栏30秒，
这些护栏不改变每界600秒探索窗口。合法操作范围由当前mission给出。

三、开发、训练与合法知识复用

允许保留并复用六公开开发环境中合法取得的数据、候选规律、记忆和白名单模型成果。九隐藏运行的观测、对话、候选、日志、新记忆和更新权重赛中均不归还，由指挥部留存；只反馈规定成绩及必要启动/格式错误。
运行器不会从其他队伍或历史评分记录中补全本次结果。每次仍独立探索、独立计费、完整计分。允许合法成果复用不改变评测期间无人干预、白名单及禁外网规则。

四、成绩与截止

截止前成功受理的冻结版本可在截止后完成评测。指挥部基础设施故障保留该版本，修复后重评；候选计算失败仍按原有无效预测规则处理。
榜单与结算选择最高的一次完整九宇宙成绩，不拼接不同提交的逐宇宙最好分数。仅返回加权总分和九宇宙各自总分，不返回分项、声明正误、验证误差或真值轨迹。
同分比较同次完整提交的各宇宙加权节约分，节约分低者排名靠前，仍相同则并列，不重跑模型或实验。加权节约分仅用于内部排序，不另行反馈。

五、实现与验收状态

客户端、会话服务、配对制品、固定推演及九界评分由指挥部运行包提供。统一命令为
python scripts/evaluate_submission.py --organizer-root <指挥部运行包目录> --output <本次结果目录>。
程序以队伍当前项目为工作目录，按清单加载实际模型，不依赖容器部署。
完整现场系统是否可用，以目标环境验收记录为准，不以接口示例或本地工程测试代替。
